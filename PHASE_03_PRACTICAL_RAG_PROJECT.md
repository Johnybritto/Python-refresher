# Phase 3: Practical RAG Project

## Goal
Build one small end-to-end retrieval project so the concepts stop feeling abstract.

## Why This Phase Matters
You can understand words like chunking and embeddings in theory, but a project is what makes the pipeline stick.

## Main Topics
- collecting a small document set
- choosing a chunking strategy
- storing chunks and metadata
- embedding and retrieval flow
- prompting with retrieved context
- returning sources
- basic evaluation of answers

## Project Style
Keep the project intentionally small.

Good examples:
- notes Q&A app
- FAQ retriever
- runbook helper
- topic-specific document assistant

## What You Should Understand By The End
- where chunking quality affects results
- where retrieval quality affects results
- how prompt wording changes grounded answers
- how to tell whether the answer really came from the source

## Practical Focus
- build one local dataset
- test a few questions
- inspect wrong answers
- improve one step at a time

## Mini Outcomes
By the end of this phase, you should build:
- one small RAG project
- one file of test questions
- one file of observed failure cases
- one short summary of what improved retrieval quality most

## Suggested Difficulty
Medium.

This should be hands-on, not theory-heavy.
