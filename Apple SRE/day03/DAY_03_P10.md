# Day 3, P10: Rolling Request Count

## Level check

At time 10 with a 5-second window, we count requests in `(5, 10]`.
Should a request at time 5 count? What about one at time 6?

## One small exercise

Implement `rolling_request_counts(timestamps, window)` in `rolling_request_count.py`.
This models counting recent requests as server events arrive.

- `timestamps` is an iterable of integer seconds, in nondecreasing order.
  Assume timestamps are valid and sorted. Duplicate timestamps represent separate requests.
- `window` is a positive integer number of seconds. Raise `ValueError` if it is <= 0,
  even for empty input. Assume its type is valid.
- For each arriving request at time `t`, return the number of requests seen so far
  whose timestamps fall in `(t - window, t]`.
- Include the current request. Exclude requests exactly at `t - window`.
- Return a list of counts; empty input returns `[]` for a valid window.
- Consume the iterable once; do not sort it or materialize the input.

Example:

```text
timestamps = [1, 2, 3, 7], window = 3
counts     = [1, 2, 3, 1]
```

For repeated timestamps `[5, 5, 5]`, return `[1, 2, 3]`: each result describes
the requests seen at that point, not future arrivals.

Use `collections.deque`, a queue supporting `append()` at the right and
`popleft()` at the left. The oldest request is at the left end.

First hint if needed: as time advances, expired requests can never become
recent again. Think about removing them before recording each count.

Target O(n) total time and O(w) working space, where w is the largest number
of requests in a window; the returned list additionally uses O(n) space.

Run from the `Apple SRE` folder:

```bash
python3 day03/rolling_request_count.py
```

The starter intentionally raises `NotImplementedError`. After your attempt,
explain the boundary condition and why removing old entries still allows O(n)
total time. During review, discuss what changes for out-of-order timestamps.
