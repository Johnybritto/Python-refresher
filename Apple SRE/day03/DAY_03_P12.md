This is Day 3's optional final exercise.

## Level check

In the sorted list `[2, 5, 8, 12, 16]`, the middle value is `8`.
If the target is `12`, which side can you discard, and why?

## One small exercise

Implement `binary_search(nums, target)` in `binary_search.py`.

- Input: a list of integers sorted in nondecreasing order, and an integer target.
- Return an index whose value equals the target, or `-1` if absent.
- When duplicates exist, any matching index is accepted.
- Empty input returns `-1`. Do not modify the list.
- Assume input is already sorted; do not sort or validate its ordering.
- Target O(log n) time for nonempty input and O(1) extra space.
- Use iteration and index boundaries, without creating list slices.

Examples:

```text
nums = [2, 5, 8, 12, 16], target = 12 -> 3
nums = [2, 5, 8, 12, 16], target = 7  -> -1
nums = [], target = 4                -> -1
```

A linear scan checks values one at a time. Sorted order lets you compare the
middle value with the target and discard a whole portion of the search range.

First hint if needed: track the first and last indices still eligible to contain
the target. After an unsuccessful comparison, the middle index must no longer
be part of the next range. Pay attention to a range containing just one element.

Run from the `Apple SRE` folder:

```bash
python3 day03/binary_search.py
```

The starter intentionally raises `NotImplementedError` until implemented.
After your attempt, explain why the range always shrinks and why halving it
gives logarithmic time. During review, discuss returning the first matching
index when duplicates exist. Day 4 practical SRE exercises follow this task.
