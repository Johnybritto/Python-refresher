# Day 3, P11: Merge Intervals

## Level check

Given closed intervals `(1, 4)` and `(3, 6)`, do they overlap? What single
interval covers both?

## One small exercise

Implement `merge_intervals(intervals)` in `merge_intervals.py`. Think of the
intervals as maintenance windows that should be combined when they overlap.

- Input: a list of `(start, end)` tuples with integer endpoints.
- Assume valid intervals: `start <= end`. Input may be unsorted.
- Intervals are closed: touching endpoints count as overlap. Thus `(1, 3)`
  and `(3, 5)` merge into `(1, 5)`.
- Return a list of tuples sorted by start, with all overlapping intervals merged.
- Do not modify the input list. Empty input returns `[]`.
- Keep disjoint intervals separate, even if their integer endpoints differ by one.
- Target O(n log n) time and O(n) extra space.

Example:

```text
[(8, 10), (1, 3), (2, 6), (15, 18)]
-> [(1, 6), (8, 10), (15, 18)]
```

First hint if needed: sort a copy by start time. Then consider whether the next
interval overlaps the last interval in your result. Watch out for a short
interval completely contained within a longer one.

Run from the `Apple SRE` folder:

```bash
python3 day03/merge_intervals.py
```

The starter intentionally raises `NotImplementedError`. After your attempt,
explain why checking the last result interval is enough and give time and space
complexity. During review, discuss what changes for half-open intervals `[start, end)`.
