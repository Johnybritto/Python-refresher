# Day 2, P08: Merge Sorted Lists

This is Day 2's optional extension, now active.

## Level check

Two sorted lists start with `1 -> 4` and `2 -> 3`. Which head should come first
in the merged list, and which input reference should advance?

## One small exercise

Implement `merge_sorted_lists(left, right)` in `merge_sorted_lists.py`.

- Inputs are heads of two finite, acyclic linked lists sorted in nondecreasing order.
- The lists do not share nodes. Values are integers; duplicates are allowed.
- Return the head of one sorted list containing every input node exactly once.
- Reuse nodes by changing their links; preserve their values.
- Either head may be `None`. Two empty lists return `None`.
- For ties, take the node from the left list first.
- Aim for O(n + m) time and O(1) extra space, using iteration.
- A temporary dummy node is allowed, but must not appear in the result.

Example:

```text
1 -> 3 -> 5 -> None
2 -> 4 -> 6 -> None

Result: 1 -> 2 -> 3 -> 4 -> 5 -> 6 -> None
```

First hint if needed: because both inputs are sorted, the smallest remaining
value must be at one of their heads. Think about tracking the result's tail.

Run from the `Apple SRE` folder:

```bash
python3 day02/merge_sorted_lists.py
```

The starter intentionally raises `NotImplementedError` until implemented.
After your attempt, explain how you handle the remaining nodes when one input
runs out, and give the time and extra-space complexity. During review, discuss
what would change if the input lists had to remain unchanged.
