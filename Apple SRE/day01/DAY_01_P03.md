# Day 1, Exercise 3: Top Error-Producing Endpoints

## Today's goal

Process log records one at a time, reject malformed records deliberately, count server errors by
endpoint, and return a deterministic top-k summary.

This is closer to everyday SRE code than the first two exercises because data may be malformed.

## Check your current level

Given this record:

```json
{"path": "/login", "status": 503}
```

Answer these before coding:

1. Is this valid JSON?
2. Is it an object?
3. Are `path` and `status` valid?
4. Should it increase the error count?

All four checks matter. Successfully parsing JSON does not automatically make the record valid.

## 1. Clarify the contract

Implement:

```python
def summarize_errors(lines: Iterable[str], k: int) -> dict:
```

Each item in `lines` represents one record. A valid record must be a JSON object with:

- `path`: a nonempty string
- `status`: an integer from `100` through `599`

Extra fields are allowed. Invalid records increase `invalid_lines` and do not affect endpoint
counts.

Count an endpoint only when its valid status is between `500` and `599` inclusive.

Return this shape:

```python
{"top": [(path, count), ...], "invalid_lines": number}
```

## 2. Identify invalid records

A line is invalid when any of these is true:

- JSON parsing fails.
- The parsed value is not a dictionary. JSON arrays, strings, numbers, and `null` are invalid.
- `path` is absent, is not a string, or is empty.
- `status` is absent, is not an integer, or is outside `100..599`.
- `status` is a Boolean.

The Boolean rule needs care because Python considers `bool` a subclass of `int`:

```python
isinstance(True, int)  # True
```

Therefore, a check for integer status must explicitly reject `bool`.

## 3. Process the iterable as a stream

Loop directly over `lines`:

```python
for line in lines:
    ...
```

Do not convert it to `list(lines)`. The caller may pass a generator or a very large file. At any
moment, you need only the current parsed record plus the dictionary of endpoint counts.

Streaming input does not guarantee constant total memory: the counts dictionary can still grow if
the logs contain an unlimited number of different error paths.

## 4. Parse safely

`json.loads(line)` can raise `json.JSONDecodeError`. Catch that specific parsing error, increment
`invalid_lines`, and continue to the next record.

After parsing, validate the result before accessing its fields. Avoid a broad `except` because it
can hide programming mistakes that are unrelated to malformed JSON.

## 5. Count valid server errors

Once a record is known to be valid:

- Status `100..499`: valid record, but do not count it as a server error.
- Status `500..599`: increase the count for its path.

A dictionary method such as `get(path, 0)` is useful for increasing a count.

## 6. Sort with two rules

The output must use:

1. Descending count.
2. Ascending path when counts are equal.

Python sorts tuples from left to right. A useful sort key is:

```python
key=lambda item: (-item[1], item[0])
```

The negative count turns Python's normal ascending numeric order into descending count order. The
path remains ascending.

After sorting, take at most `k` results. If `k <= 0`, the top list is empty, but every line must
still be processed so invalid records are counted.

## 7. Complexity target

Let `C` be the total number of input characters and `m` the number of distinct error endpoints.

- Parsing and counting: O(C)
- Sorting endpoint counts: O(m log m)
- Count storage: O(m), apart from the current parsed record

## Completed solution walkthrough

The function keeps two pieces of state:

```python
error_counts = {}
invalid_lines = 0
```

`error_counts` maps each error path to its number of 5xx responses. `invalid_lines` records inputs
that fail parsing or validation.

The loop processes one input string at a time:

```python
for line in lines:
    try:
        record = json.loads(line)
    except json.JSONDecodeError:
        invalid_lines += 1
        continue
```

`json.loads` converts a JSON string into a Python value. Broken JSON raises `JSONDecodeError`.
After counting that failure, `continue` moves directly to the next input record.

Valid JSON is not necessarily a valid log object, so the next check requires a dictionary:

```python
if not isinstance(record, dict):
    invalid_lines += 1
    continue
```

The required fields are retrieved with `.get()`, which returns `None` for a missing key:

```python
path = record.get("path")
status = record.get("status")
```

The combined condition rejects a non-string or empty path, a Boolean or non-integer status, and
an integer outside the HTTP range:

```python
invalid_record = (
    not isinstance(path, str)
    or path == ""
    or isinstance(status, bool)
    or not isinstance(status, int)
    or not 100 <= status <= 599
)
```

The explicit Boolean check matters because `isinstance(True, int)` is `True` in Python. Invalid
records are counted and skipped. Valid non-5xx records remain valid but do not increase an endpoint
error count.

For a valid server error, `.get(path, 0)` supplies zero when a path has not appeared before:

```python
if 500 <= status <= 599:
    error_counts[path] = error_counts.get(path, 0) + 1
```

`error_counts.items()` produces `(path, count)` tuples. The sort key uses the count at index `1`
and the path at index `0`:

```python
sorted_errors = sorted(
    error_counts.items(),
    key=lambda item: (-item[1], item[0]),
)
```

Negating the count places larger counts first. When counts match, Python compares the second part
of the key and sorts paths alphabetically. For example:

```text
("/login", 2)  -> (-2, "/login")
("/search", 1) -> (-1, "/search")
("/api", 1)    -> (-1, "/api")
```

The first `k` sorted results are selected only for a positive `k`:

```python
top_errors = sorted_errors[:k] if k > 0 else []
```

The function still parses every line before this decision, so invalid records are counted even
when the requested top list is empty. It finally returns both results:

```python
return {
    "top": top_errors,
    "invalid_lines": invalid_lines,
}
```
